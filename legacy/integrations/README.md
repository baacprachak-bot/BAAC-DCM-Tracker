# เชื่อมกับระบบ Worker ที่ใช้อยู่

ไฟล์ในโฟลเดอร์นี้ต่อยอดจาก webhook Worker ที่ผู้ใช้ส่งมา ไม่ใช่การ deploy และไม่ใช่โค้ดหน้าฟอร์ม `baac-dcm-form` โปรเจกต์ Node.js ที่ราก repository เป็นระบบต้นแบบอีกชุดหนึ่ง และไม่ได้ใช้ฐานข้อมูลเดียวกับ Google Apps Script โดยอัตโนมัติ

## สิ่งที่เตรียมให้

- `line-webhook.js`: คงคำสั่งเดิมของ Worker เพิ่ม “รายการอนุมัติแล้ว” และชื่อย่อ “อนุมัติแล้ว” รวมถึง “รออนุมัติ” มี timeout สำหรับการอ่านรายการ ไม่คืนข้อมูลผ่านแชตกลุ่ม ตัดการ log เนื้อหาเอกสาร และจำกัดความยาวข้อความตอบกลับ
- `rich-menu.json`: โครง 3 ช่อง ช่องแรกเปิด LIFF `2012048449-ZBktvJBu` อีกสองช่องส่งข้อความ “รายการรออนุมัติ” และ “รายการอนุมัติแล้ว” กลับเข้า webhook ส่วนการอนุมัติให้พิมพ์ `อนุมัติ <CIF>` ในแชตส่วนตัว ตามพฤติกรรมเดิม
- ทดสอบด้วย `npm test` การทดสอบ Worker ใช้ backend จำลอง จึงไม่ยืนยันการจัดเก็บหรือสิทธิ์ใน Google Apps Script จริง

## ส่วนที่ยังต้องตรวจใน Google Apps Script

ต้องได้รับโค้ด Apps Script และโค้ด form Worker ก่อน จึงจะตรวจ schema, บัญชีเจ้าหน้าที่, การบันทึก และเพิ่ม action ที่เข้ากันได้โดยไม่เดาชื่อชีตหรือคอลัมน์

Worker เดิมใช้ `register`, `listPendingCustomers`, `approveCustomer`, `registerDocument`, `createBatch`, `confirmBatch` รวมทั้งค้นหาเอกสารด้วย GET

ส่วนที่เพิ่มต้องการ Apps Script action `listApprovedCustomers` โดยรับ POST:

```json
{"key":"<จาก secret ที่ตั้งไว้>","action":"listApprovedCustomers","lineUserId":"<จาก LINE event ที่ตรวจลายเซ็นแล้ว>"}
```

Apps Script ต้องตรวจ API key และตรวจว่า lineUserId เป็นเจ้าหน้าที่ที่ active ในตำแหน่งผู้ช่วยผู้จัดการสาขาหรือผู้จัดการสาขาก่อนอ่านข้อมูล ส่งผลรูปแบบเดียวกับรายการรออนุมัติ:

```json
{"success":true,"count":1,"customers":[{"customerName":"ข้อมูลสมมติ","cif":"001234"}]}
```

`count` ต้องเป็นจำนวนเต็ม และ `customers` ต้องเป็น array เมื่อไม่มีข้อมูลใช้ count 0 และ array ว่าง หากไม่มีสิทธิ์ใช้ `{"success":false,"error":"PERMISSION_DENIED"}` ห้ามให้ผู้เรียกเลือกตำแหน่งเอง การส่ง lineUserId มาอย่างเดียวไม่ใช่การยืนยันตัวตนสำหรับ API สาธารณะ ต้องตรวจ shared key ฝั่ง Apps Script ด้วย

ก่อนเปิดใช้งาน ต้องตรวจเพิ่มว่าหน้าฟอร์มตรวจ LINE ID token ที่ backend, จำกัดผู้บันทึกเป็นหัวหน้าฝ่ายสินเชื่อ/หัวหน้าหน่วย, เก็บ CIF เป็นข้อความรักษาศูนย์นำหน้า และการอนุมัติป้องกันรายการซ้ำพร้อมบันทึกผู้อนุมัติและเวลา

## เมื่อส่วน backend พร้อมและตรวจแล้ว

1. สำรองโค้ด webhook Worker ปัจจุบัน แล้วนำ `line-webhook.js` ไปใช้กับ Worker ที่รับ `/webhook` ของ Messaging API อย่านำไปทับ form Worker ซึ่งเสิร์ฟหน้า LIFF
2. คง secret binding ชื่อ `LINE_CHANNEL_SECRET`, `LINE_CHANNEL_ACCESS_TOKEN`, `GOOGLE_SCRIPT_URL`, `DCM_API_KEY` เดิม ไม่ส่งค่ามาในแชต
3. ใน LINE OA Manager สร้าง Rich Menu แบบสามช่อง: “บันทึกลูกค้า” เป็นลิงก์ LIFF ส่วน “รออนุมัติ” และ “รายการอนุมัติแล้ว” เป็นการส่งข้อความตาม JSON ต้องใช้ภาพเมนูด้วยหากสร้างผ่าน API ไม่มีการสร้างหรือผูกเมนูจริงในงานนี้
4. ทดสอบด้วยข้อมูลสมมติครบสามตำแหน่ง รวมผู้ไม่มีสิทธิ์ ข้อมูลหลัง refresh และการอนุมัติซ้ำ ก่อนใช้ข้อมูลจริง

ยังไม่มีการ deploy, เรียก API เพื่อแก้ไข LINE หรือเปลี่ยนฐานข้อมูลจริง
